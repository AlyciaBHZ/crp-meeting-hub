# Administrator file deletion

The user requests administrator file deletion and has authorized direct publication to the existing site. Extend the existing named-slide deletion flow to legacy archive PDFs and meeting minutes, with visible Delete buttons. Confirmation names the file, warns that deletion is permanent, and explains that PDF discussions are retained. Minutes deletion remains accessible on collapsed meetings; successful deletion returns the meeting to its missing-minutes/upload state.

Reuse the authenticated Storage API to delete bytes, then clean up database metadata. Never delete storage.objects through SQL in production. A failed storage request stops metadata cleanup; a failed cleanup remains retryable. Backend policies restrict new legacy/minutes storage deletion to admins. Legacy reservation cleanup also accepts admins deleting another uploader's file but continues protecting stored files; minutes cleanup requires admin, matching path and absent storage. New policies grant no access to unrelated buckets.

Validation covers cancellation, pending buttons, errors/retry, member UI restrictions, storage-before-metadata coordination, real PostgreSQL RLS/RPC behavior, and browser checks with synthetic files. Do not delete any existing production file while implementing this capability. Apply the additive permission migration before deploying UI through GitHub/Vercel.

Review identified stale minutes replacement as a deletion risk. Each new upload now uses a unique object path, with fresh metadata checked before deleting. RPC cleanup verifies the original path again after Storage removal. This preserves a concurrent replacement. The prior object is cleaned up only after replacement metadata succeeds. If the metadata response fails, retain both objects because the server may already have committed; this can leave an unreferenced object requiring administrator cleanup, but avoids destroying a current file. Minutes UI refreshes after success or failure.
